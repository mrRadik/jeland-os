# Jeland OS — 0.6.5 / Rear seats + Automations preview

0.6.5: в окне пассажирского сиденья вместо общего переключателя заднего ряда —
две отдельные карточки: «Заднее левое» и «Заднее правое», уровни подогрева 0–3.
Для задних вентиляция отсутствует. Команда одного места не меняет второе или передние.
В ГУ используются существующие CAR 139 / 141, wire 1–4, индикация по GET/events;
разрешение записи и проверка свежего состояния выбранного места сохраняются.
В DEMO уровни хранятся независимо, прежний общий выбор переносится в уровни 0/1.
В направлениях обдува убраны острые стрелки: мягкие потоки у лица/ног и только
контур стекла для «На лобовое». Отдельная кнопка обдува лобового не удалялась.

0.6.4: 39 стандартных пиктограмм Lucide 0.468.0 вместо прежних ручных контуров;
автомобильные символы отдельно выровнены на 24-unit сетке. Лицензия включена
в assets/licenses/lucide.txt; приложение не загружает иконки из сети.
Температуры нижней панели показаны целыми числами без градуса, строго по центру
между − и +. Это форматирование: дробные DEMO-уставки округляются для отображения,
модель и команды не меняются; LO/HI/нет данных сохранены.
Вентилятор вращается в меню климата и нижней панели при включённом питании,
свежем известном fan > 0; быстрее при большей ступени. Выключен/нет данных —
неподвижен. Анимация сама не отправляет никаких команд.

0.6.3: вместо векторного значка в деталях шины — фотореалистичное колесо на
прозрачном фоне. Резина и металлический диск сохраняют собственные материалы,
без перекрашивания под цвет интерфейса; размер 84 dp. Показания и команды не менялись.

0.6.2: значок шины заменён на круглое колесо с ободом, ступицей и пятью спицами,
без наружных штрихов. Канал температуры шин ещё не восстановлен: live-модель
не получает его из имеющегося вектора давления /140. В SDK /143 означает единицу
температуры, /144 — предупреждения, /173–176 — предупреждения положения колёс.
Эти значения не преобразуются в градусы. На ГУ вместо DEMO остаётся «Нет данных»;
это ограничение текущей интеграции, не утверждение об отсутствии датчиков в машине.

0.6.1: возвращён отдельный «Обдув лобового» в меню климата и нижнюю панель.
Это прежний toggleDefrost / HVAC 24, не обогрев лобового (HVAC 65) и не выбор
направления обдува. Общая блокировка при выключенном/неизвестном питании сохранена.
Окно шторки использует изображение J7 из блока состояния автомобиля: полотно
уходит слева направо, анимация следует локально выбранной команде, не задержанному
feedback. Неизвестное положение не изображается как наполовину открытое.
Нижняя панель скруглена со всех четырёх сторон, с небольшим внешним отступом.
Автоматизации по-прежнему только MOCK; Probe не изменён этой доработкой.

0.6.0: самостоятельный раздел «Автоматизации» между «Автомобиль» и «Приложения».
Правила сохраняются в Room: создать, изменить, включить/выключить, удалить с
подтверждением. Два компонента: все четыре сиденья одним правилом или шторка.
Передние сиденья: подогрев/вентиляция, задние: только подогрев. Для каждого
параметра есть «Не изменять», 0, 1, 2, 3; KEEP не равен выключению.
У сидений — условие ниже/выше температуры; у шторки — полностью/наполовину,
без температуры. Редактор и список используют существующие Dark/Light/Auto.

Важно: автоматизации сейчас только MOCK. Их отдельный исполнитель не связан с
VDS и не меняет даже обычные рабочие репозитории климата/сидений Jeland OS.
Запускаются исключительно через «Тестовая поездка · MOCK» → «Новая сессия».
Открытие приложения/переход по меню ничего не выполняет. Самостоятельного
определения зажигания/начала поездки и фонового исполнения в этой версии нет.

Сессия фиксируется до выполнения: повтор и перезапуск приложения не переигрывают
правила. Неизвестная/устаревшая температура пропускает сиденья. Побеждает больший
приоритет, при равенстве — последнее изменённое правило для всего компонента;
KEEP не дополняется действиями проигравших правил. Изменения — со следующей сессии.
Инструкция, архитектура и ограничения: [docs/AUTOMATIONS.md](docs/AUTOMATIONS.md).
Проверка: [docs/QA-0.6.0.md](docs/QA-0.6.0.md).

0.5.0: живые индикаторы Wi-Fi, Bluetooth и мобильной связи. Отдельно учитываются
включение радио и подключение: Wi-Fi читается даже когда это не сеть по умолчанию,
Bluetooth — по автомобильным профилям аудио/телефона, мобильный сигнал — из кэша
CarLan (GET 720899) с резервным чтением Android. Нет данных — нет выдуманных полосок.
Обновление только при видимом приложении; без поиска устройств и смены сетей.
При необходимости: Настройки → Индикаторы связи → Разрешить чтение индикаторов.

Кнопка «Автомобиль» открывает штатные настройки Desay; на BlueStacks — настройки
Android. Прежняя внутренняя DEMO-панель сохранена в Настройках отдельной кнопкой.

Погода: собственного запроса прогноза нет, разрешение INTERNET не добавлено.
На ГУ виджет открывает установленную com.liontech.weather только по нажатию.
Пока нет подтверждённого способа прочитать полный закрытый MMKV-кэш или встроить
чужое окно: температура показана «—°», не +8° из DEMO. GET WEATHER_NEWS в полевом
логе пустой, а его DTO не содержит полного текущего прогноза. Штатная погода может
сама обновляться при ручном открытии; наше приложение её не запускает в фоне.
На локальном DEMO без штатной погоды сохранён явно подписанный тестовый прогноз.
Подробности и проверка: [docs/QA-0.5.0.md](docs/QA-0.5.0.md).

0.4.9: новый векторный значок рециркуляции по пользовательскому образцу —
боковой контур автомобиля с возвратной стрелкой. Один ресурс в меню климата и
нижней панели. Размеры кнопок, команды, индикация и блокировка питания не менялись.

0.4.8: при выключенном либо неизвестном питании климата заблокированы температура,
вентилятор, направления, AUTO, A/C, рециркуляция, обогревы стёкол и SYNC — как в
popup, так и в нижней панели. Не только оформление: DEMO-репозиторий и live-отправка
также отклоняют изменения. Питание и открытие панели доступны; сиденья независимы.
После включения на ГУ элементы активируются по свежему статусу питания.

Шторка: анимация, выделенная кнопка и подпись следуют принятой локальной команде,
а не задержанному/несогласованному feedback. Следующая команда шторки не ждёт
обратного чтения предыдущей; каждый SET отправляется ровно один раз.
Телеметрия читается отдельно, остаётся в журнале и не переписывается командой.
При ошибке отправки локальный выбор возвращается к предыдущему; при заблокированной
записи картинка не меняется. Это отображение выбранной команды, не замер положения.
Выбор не сохраняется между live-сессиями, при подключении команды не переотправляются.

RAW и SET/GET/readback убраны из основного UI, включая всплывающие отчёты,
шторку, давление, топливо и экран подключения. Журналирование и ZIP-экспорт сохранены.
Короткие сообщения об ошибке/запрете команды остаются; предупреждения дверей не менялись.

## Запуск и сборка

Открыть эту папку в Android Studio, выбрать JDK 17, установить SDK Platform 35 и Build Tools 34.0.0.
Согласиться с лицензией SDK в Android Studio/SDK Manager. Gradle 8.9, AGP 8.7.3, Kotlin 2.0.21,
Compose BOM 2024.12.01. Файл local.properties содержит локальный путь SDK и не распространяется.

На текущем компьютере: `powershell -ExecutionPolicy Bypass -File .\BUILD.ps1 -Tests`.
Для установки/открытия в локальном BlueStacks: двойной клик `RUN-BLUESTACKS.cmd`.
По умолчанию используется `127.0.0.1:5556`, другой локальный порт можно передать в PS1 через `-Serial`.
Этот помощник намеренно не принимает USB-устройства и не устанавливает APK на ГУ.
На другом: `gradlew.bat assembleDebug testDebugUnitTest` (SDK должен быть установлен).
APK: `app/build/outputs/apk/debug/app-debug.apk`. Отладочная подпись; не production-релиз.
Не заменяйте ключ подписи между обновлениями установленной версии без удаления приложения.

UI-тесты на локальном Android 11 / BlueStacks: установить debug APK и test APK,
выполнить `adb -s SERIAL shell am instrument -w ru.jeland.os.test/androidx.test.runner.AndroidJUnitRunner`.
Не выбирать автоматически первое устройство: тесты предназначены для локального эмулятора, не машины.

## Что работает в демо

- Главная: J7 в горах, системные часы/дата, mock-погода, топливо в литрах, музыка, mock-карта, визуальное состояние кузова/шин, избранное и быстрые действия.
- Постоянные хедер, меню из шести кнопок и симметричная климат-панель. Шесть независимых маршрутов.
- Топливо: бак 55 л, остаток и до полного. Оценочный объём помечен; отсутствующие данные не выдумываются.
- Строгий top-down вид J7: нос слева, водительская левая сторона внизу. ПЛ снизу слева, ПП сверху слева, ЗЛ снизу справа, ЗП сверху справа.
- Четыре независимых показания шин: норма/предупреждение/критично/нет данных. Пороги тестовые, редактируются и сохраняются, не являются заводскими нормами.
- Шестерёнка карточки кузова открывает симулятор: несколько дверей, капот, багажник, движение, топливо и шины.
- Постоянная машина поверх hero удалена. На стоянке открытие показывает компактное событие на 4 секунды; закрытие убирает его раньше. У каждой зоны свой таймер, без повторного показа из-за обновления шин/топлива.
- После движения с открытым кузовом предупреждение остаётся до закрытия всех зон, в том числе после остановки. Если всё закрыто, уведомлений нет. Только MOCK, без системных уведомлений и overlay-разрешений.
- Нажатие на колесо или его показания открывает давление и температуру именно этой шины. Нажатие на кузов — расширенную панель с шестью независимыми DEMO-переключателями и тестовым движением.
- Избранное настраивается через popup: реальные launcher-приложения и значки с устройства, поиск, запуск, звезда и изменение порядка. Неназначенные ярлыки не выдаются за установленные приложения.
- Полноценный раздел приложений: общая сетка, поиск с очисткой, фильтр избранного, редактор порядка, пустые/ошибочные состояния и обновление списка. Popup настройки ярлыков сохранён.
- Автомобиль: существующая иллюстрация J7 и быстрые функции; вкладки «Быстрые», «Освещение», «Двери и замки», «Комфорт», «Вождение», «Другие». Все параметры только локальные и сохраняются. Управление замками/ассистентами не выполняется.
- Настройки: Dark/Light/Auto, mock-день/ночь, показ топлива/кузова/избранного на главной, доступ к симулятору, состояние подключений и сведения о приложении.
- Связь в хедере — доступные сведения Android ConnectivityManager/TelephonyManager. Неизвестный сигнал остаётся неизвестным; телефонные/гео-разрешения не запрашиваются.
- Температура 16–32 °C с шагом 0,5, вентилятор 0–7, направление, AUTO, A/C, рециркуляция, обдув, SYNC.
- Независимые панели сидений: подогрев/вентиляция 0–3, подогрев заднего ряда в панели пассажира.
- Подогрев руля, анимированная шторка, зеркала и симулятор открытых зон кузова — только локальные значения.
- Музыка: смена трека, прогресс, пауза, перемотка, избранное, источник и демонстрационная громкость. Звука нет.
- Навигация: смена демонстрационной цели, манёвра и масштаба; единое состояние для mock bridge.
- Тёмная / светлая / Auto. Auto использует ручной тестовый DayNightProvider.
- Основные настройки, тема, избранное/порядок, лайк трека и тестовые пороги сохраняются в SharedPreferences. Воспроизведение, прогресс, открытия дверей, топливо/шины и активность маршрута — состояние сессии.

Отдельного утверждённого изображения автомобиля с вкладками в материалах не было: сохранена существующая композиция, добавлены требуемые вкладки в том же стиле.
Камеры — иллюстрация с явной подписью «нет видеосигнала», не парковочный ассистент.
Все погодные/навигационные/автомобильные значения вымышленные. Названия треков — метаданные без аудиофайлов.

## Структура

```
app/src/main/java/ru/jeland/os/
  core/          модели, интерфейсы репозиториев, DayNightProvider, ClusterBridge
  data/          mock-реализации, хранилище настроек, контейнер зависимостей
  ui/theme/      единые цвета, типографика, отступы и формы
  ui/            Compose-экраны, панели, виджеты, ViewModel
```

MVVM + StateFlow + Navigation Compose; конструкторное внедрение зависимостей без Hilt.
UI не обращается к Android vehicle API. Для будущего подключения заменяются реализации семи репозиториев,
а не обработчики кнопок. MockClusterBridge хранит NavigationState только в памяти, не рисует на приборке.
Добавлены отдельные репозитории приложений, состояния связи и параметров интерфейса. Ресурсы/значки
приложений загружаются вне UI-потока. Callback связи зарегистрирован только при видимом приложении,
таймер mock-плеера не работает в фоне. Новые навигационные SDK и реальная передача данных в ПП не добавлялись.

## Безопасные границы

Нет CAN/VDS/Binder/HAL, automotive-разрешений, root, overlay, internet, Bluetooth и геолокации.
Используется только normal ACCESS_NETWORK_STATE и запрос видимости MAIN/LAUNCHER; нет QUERY_ALL_PACKAGES.
Не запускается Activity/Presentation на display 2, не трогаются Kanzi, warning icons и штатные сервисы.
Приложение не регистрируется HOME-launcher, не включает kiosk и не управляет настройками устройства.
Прототип нельзя использовать вместо штатных средств управления автомобилем или приборки.

## Графика

Hero, нейтральное сиденье и top-down J7 созданы с навыком imagegen по референсам пользователя; PNG скопированы в
`app/src/main/res/drawable-nodpi`. Это художественные иллюстрации, не OEM-ресурсы и не точная модель CAD.
Карта, двери, рамки, иконки и эффекты состояний — нативная графика Compose. Пиктограммы новой главной
собраны на единой сетке 24×24 с толщиной 1,55. Большая библиотека material-icons-extended удалена.
Промпты и происхождение: `docs/ASSETS.md`, `docs/TOP-VIEW-ASSET.md`. Приборка не заменяется.
