# Обновление приложения через GitHub Releases

Источник: https://github.com/mrRadik/jeland-os — публичный репозиторий релизов.
Можно хранить только APK и описание обновления; публиковать исходники не требуется.
Пока репозиторий приватный или в нём нет релиза, проверка покажет недоступность.
GitHub-токен, аккаунт пользователя и отдельный сервер на ГУ не нужны.

## Что уже добавлено в исходники

Настройки → «Обновление Jeland OS»:

- Автопроверка при открытом приложении, не чаще одного раза в 6 часов.
  После ошибки остаётся предыдущая информация о скачанном обновлении.
- Кнопка принудительной проверки, версия и время последней успешной проверки.
- Автозагрузка по Wi-Fi без ограничения трафика — отдельно включаемая опция,
  по умолчанию выключена. На мобильной/лимитной сети нужна отдельная кнопка
  и подтверждение размера. При потере подходящего Wi-Fi автозагрузка прекращается.
- Загрузка в закрытую папку приложения, ограничение размера 512 МиБ,
  проверка размера и SHA-256, applicationId, versionCode, versionName, minSdk,
  совпадения подписи с уже установленным Jeland OS. Проверка повторяется перед
  открытием установки. Нельзя понизить версию или подменить ключ подписи.
- Только пользовательская установка через системный установщик Android,
  после подтверждения стоянки. Если нужно — штатный экран разрешения установки
  из этого источника. Нет root, тихой установки или изменений прошивки.

Проверка активна только при открытом приложении; ночного фонового расписания нет.
Загрузка продолжается при закрытии экрана настроек, пока процесс приложения жив.
Если Android завершит процесс во время загрузки, её нужно повторить кнопкой;
частичный файл не предлагается к установке. Проверенный готовый файл сохраняется.
После следующей успешно проверенной загрузки удаляются только устаревшие APK
из собственной папки updates/ready, не приложения, пользовательские файлы или логи.

## Доступ для публикации

Установить интеграцию GitHub, подключить свой аккаунт и разрешить репозиторий
mrRadik/jeland-os. Для создания релизов/прикрепления файлов нужны права записи
в Contents этого репозитория. Для чтения публичного релиза с ГУ авторизация
не требуется. Не передавать токены, пароль или ключ подписи в чат/APK/репозиторий.

## Подготовка каждого релиза

1. По отдельной команде пользователя собрать APK с увеличенным versionCode.
   Текущая установленная линия — versionCode 70; следующая должна быть выше.
2. Подписывать **тем же ключом**, которым подписана текущая установленная версия.
   Потеря/смена debug-ключа на другом компьютере тоже нарушит совместимость.
   Новый production-ключ нельзя просто подставить без отдельного плана миграции.
3. Имя файла: JelandOS-<версия>.apk. По готовому файлу выполнить:

   `./tools/New-GitHubUpdateManifest.ps1 -ApkPath <готовый APK>`

   Скрипт читает параметры готового APK и создаёт рядом jelandos-update.json;
   ничего не собирает, не подписывает и не публикует. При необходимости указать
   -AaptPath и -OutputDirectory. Не писать версию/хеш вручную.
4. В ОДИН публичный стабильный GitHub Release загрузить APK и
   jelandos-update.json. Оба файла должны быть в разделе Assets, не только
   в коде репозитория. Не помечать Draft/Pre-release. Например tag v0.9.30
   без слеша. Этот релиз должен быть выбран GitHub как latest.
5. Сначала один раз поставить версию с механизмом обновления через обычный
   установщик. Уже установленный старый APK не получит новый код самостоятельно.
6. Проверить на стоянке: поиск версии → загрузка → системное разрешение →
   системный установщик → версия приложения/сохранение настроек.

Формат jelandos-update.json (значения ниже — пример, не готовый релиз):

```json
{
  "schema": 1,
  "applicationId": "ru.jeland.os",
  "versionCode": 71,
  "versionName": "0.9.30",
  "minSdk": 30,
  "apkName": "JelandOS-0.9.30.apk",
  "size": 218000000,
  "sha256": "<64 шестнадцатеричных символа из готового файла>"
}
```

Сопоставление ведётся по versionCode, а не строке имени версии.
Источники загрузки фиксированы: конкретный репозиторий, один релиз для обоих
файлов, HTTPS; разрешённые перенаправления только к узлам GitHub release assets.
FileProvider открывает только updates/ready, не staging/логи/всё хранилище.
