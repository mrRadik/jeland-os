# Jeland OS 0.8.1-navhost-beta

20 октября 2026, versionCode 40, main. Бесплатный эксперимент встраивания,
не объявляется готовой навигацией. 0.8.0 оставлен отдельным прежним APK.

## Реализация

Обычному UID приложения по-прежнему запрещено встраивать эти Activity. Но
локальный Android11 предоставляет UID shell разрешения INTERNAL_SYSTEM_WINDOW,
ACTIVITY_EMBEDDING и INJECT_EVENTS. Вместо выдачи их приложению создан отдельный
ограниченный процесс app_process, запускаемый пользователем через ADB.

Помощник создаёт собственный VirtualDisplay, передаёт его изображение в
SurfaceView Jeland OS и запускает выбранный навигатор на ЭТОМ новом дисплее.
Нет обращения к физической приборке, дисплею 2 по константе или OEM AreaDisplay.
Идентификатор берётся исключительно из созданного контейнера. Он проверяется
на ненулевое значение; данные ввода всегда адресуются только ему.

Принимаются ровно два пакета: ru.dublgis.dgismobile и ru.yandex.yandexnavi.
Команды: состояние, подключить поверхность, отключить поверхность, до двух
пальцев, BACK, открыть заново и остановиться. Нет строк shell-команд, произвольных
пакетов/клавиш/дисплеев, сетевого порта, чтения аккаунтов или файлов навигаторов.
Координаты касаний конечны и ограничены размерами контейнера; источник touch
задаётся помощником. Binder принимает только UID установленного Jeland OS.

Регистрация — ContentProvider, защищённый DUMP и дополнительной проверкой
вызывающего UID=2000. В том числе обычный UID самого приложения не может
подменить Binder помощника. Остановка доступна через приложение или отдельный
вызов ADB. При смерти процесса Jeland OS помощник освобождает свой дисплей
и завершает работу. На загрузку системы ничего не прописывается.

Процесс имеет права ADB: это существенное отличие от обычного приложения.
Пользователь явно подтверждает активацию START → N; автоматического запуска
при установке APK нет. Ключ -Yes разрешён только для локального 127.0.0.1.
Root, setenforce, подпись платформой, priv-app, grant скрытых разрешений,
модификация чужих APK или прошивки не используются. Настройки автомобиля не
меняются. Эта beta поддерживает проверенный API30; другие прошивки могут
запретить необходимые служебные вызовы.

## Интерфейс

Выбор навигатора — только в настройках. При наличии помощника и установленного
провайдера вкладку занимает SurfaceView, а не рисованная карта/веб-сайт.
Вокруг остаются меню, часы и климат. SurfaceView в этой реализации находится
над главным графическим слоем; поэтому при климатической панели, сообщении
или предупреждении об открытых элементах поверхность карты скрывается. Иначе
она могла бы закрыть элементы управления. После закрытия панели подключается
прежний контейнер, без повторного запуска маршрута.

При уходе с вкладки поверхность отключается, но контейнер сохраняется на время
жизни помощника. Смена провайдера закрывает предыдущий контейнер. Крестик
в заголовке или «Отключить помощник» закрывает контейнер. Это может завершить
Activity/маршрут навигатора; сохранность ведения при остановке НЕ обещается.
Если BACK закрыл корневой экран навигатора, есть «Открыть заново».

## Что действительно проверено

- Успешная сборка и 111 модульных тестов.
- Финальная регрессия: 14 инструментальных проверок (InstalledNavigation 6,
  DashboardPolish 1, MusicMarquee 1, Connectivity 5, обычный embedding audit 1)
  и отдельно 1 проверка транспорта bridgeHostsNavigatorAndForwardsTouchInsideJeland.
  Все перечисленные прошли. Проба рендера отдельно не прошла, см. ниже.
- Активация и отключение Jeland-Navigation-Host.ps1 реально проверены из
  Windows PowerShell на локальном 127.0.0.1:5556; после отключения status=false.
  Скрипт сохранён с BOM для корректного русского текста в PowerShell 5.1.
- Локальный Android11: отдельный помощник реально запущен как UID2000,
  зарегистрирован через Binder, Activity 2ГИС размещена в созданном контейнере.
- Получено изображение из 2ГИС в границах вкладки, включая заставку; при первом
  эксперименте был кадр с картой/маршрутом. Не установлено, было ли это реальное
  ведение или встроенная демонстрация самого навигатора. Это не доказательство GPS.
- Проверка bridgeHostsNavigatorAndForwardsTouchInsideJeland прошла: создание
  контейнера, постановка DOWN/UP в InputManager нужного дисплея, видимость меню
  и климата, скрытие поверхности при popup климата, возврат после закрытия popup
  и перехода Главная → Навигация, остановка помощника. Проверка счётчика ввода
  НЕ доказывает, что каждый элемент интерфейса навигатора правильно отреагировал.
- Отдельно обычный UID приложения всё ещё получает запрет прямого embedding;
  работа помощника не маскируется под изменение прав самого APK.

## Неудачные проверки и ограничения — важно

Стабильная карта на BlueStacks НЕ подтверждена. Проба renderProbe=true,
ожидающая разнообразный кадр 30 секунд, завершалась таймаутом. Были белые окна
и сбои самих навигаторов; у 2ГИС встречались native-crash и ошибка KeepaliveService,
у Яндекса ранее SIGNALED/status6 также при отдельном запуске. TextureView не дал
стабильного кадра; текущий beta использует SurfaceView. У 2ГИС проверялись ARM64
и ARM32 варианты исполнения того же официального APK. На физический ГУ эти
изменения/пакеты НЕ устанавливались. Нельзя переносить успех Binder-теста на
полную навигацию или списывать все проблемы на эмулятор без проверки автомобиля.

Тестовый профиль 2ГИС, созданный нами на эмуляторе без аккаунта, очищался для
повторного первого запуска. Потерян только этот тестовый кэш; личные приложения
и данные пользователя не очищались. После прерванного теста прежние car.live
и выбранный провайдер восстановлены отдельной QA-процедурой; обычные QA-запуски
используют QaPreferenceGuard.

Не проверены GPS/офлайн-поездка, голос, клавиатура поиска в дочернем дисплее,
диалоги разрешений, мультитач на реальном ГУ, длительная работа/нагрев, устойчивый
рендер обоих провайдеров, сохранность маршрута при сворачивании и работе климата.
Наличие изображения приложения не считается решением этих пунктов.

## Проверка на ГУ — только стоя

1. START → 1 → установить JelandOS-0.8.1-navhost-beta.apk. Навигаторы уже должны
   быть установлены. Сначала открыть выбранный навигатор отдельно и убедиться,
   что он вообще запускается, настроен и имеет необходимые разрешения/карты.
2. Открыть Jeland OS. Подключить ADB, START → N и подтвердить предупреждение ДА.
   Вариант без меню — ENABLE-NAVIGATION.cmd. После перезагрузки/обновления OS
   этот запуск нужен заново. Помощник не запускается сам из обычного APK.
3. Настройки OS → Навигация → выбрать установленное приложение.
4. Вкладка Навигация: проверить карту, панорамирование, поиск и кнопку BACK.
   Проверить, что меню/климат не закрыты картой. Открыть климат: его окно должно
   быть доступно, карта на время скрывается. Никаких тестов в движении.
5. Если окно пустое — крестик в заголовке отключает помощник. Не считать
   «ADB-помощник подключён» подтверждением работы карты. Запустить навигатор
   отдельно; не применять повторные команды бесконечно.
6. После теста START → L. В архив добавляются NAV_HOST/NAV_* в журнале OS,
   короткий /data/local/tmp/jeland-navhost.log и dumpsys package двух провайдеров.
   APK, базы карт и приватные данные навигаторов не копируются.

Для продолжения нужны результат и логи именно с Qualcomm ГУ: изображение,
касания, клавиатура и независимый запуск выбранного навигатора. SDK не покупаем.
