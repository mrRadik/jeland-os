# 0.5.0 — связь, штатные настройки и погода без второй загрузки

## Реализация

- Wi-Fi: включение, наличие подключения и RSSI; callback всех сетей, broadcasts и
  резервное чтение раз в 3 секунды при видимом приложении. Не зависит от того,
  выбран ли Wi-Fi сетью по умолчанию. Нет сканирования, чтения списка точек,
  SSID/BSSID, подключения и изменения сетей.
- Bluetooth: включение и состояния автомобильных профилей A2DP Sink (11) /
  Headset Client (16). Подключённый телефон выделяет значок голубым. Недоступный
  профиль не трактуется как успешное подключение. Нет discovery, pairing,
  connect/disconnect и управления музыкой в этой версии.
- Мобильная связь: GET-only кэш CarLan, event 720899 TBOX_NETWORK_STATUS, ключ
  data, Parcelable VDNetworkStatus. Только 0…4 трактуется как уровень; сырой
  Android ASU=26 не превращается в полные полоски. Резерв — TelephonyManager,
  если доступен. Истёкший ответ CarLan не используется через 30 секунд.
- CarLan читается раз в 10 секунд, максимум один GET в работе. Нет накопления
  очереди при зависшем Binder; поздний ответ после pause игнорируется. При
  уходе с экрана callback/receiver снимаются, прокси закрываются, bind отменяется.
- Новые разрешения: ACCESS_WIFI_STATE, BLUETOOTH (до API 30), BLUETOOTH_CONNECT,
  READ_PHONE_STATE. Опасные разрешения запрашиваются по явной кнопке в Настройках.
  Отказ не ломает остальные индикаторы. INTERNET, location, scan, CHANGE_WIFI_STATE
  и overlay не добавлены. OEM permission ivi.vds.permission.SERVICE уже был.
- Изменения статуса и ошибки включены в существующий журнал INTEGRATION; ZIP из
  приложения и START → L продолжают собирать его. SSID/MAC/имена телефонов/IP не
  записываются новым наблюдателем.

## Кнопка «Автомобиль»

Открывает экспортированную com.desaysv.setting.ui.activity.SettingActivity с
com.desaysv.vehiclesetting.ACTION_VEHICLE_SETTING. Имя и action подтверждены
дампом integration-com.desaysv.setting-package.txt. Без Desay (BlueStacks) —
обычные настройки Android. При запрете запуска показывается короткая ошибка,
не выполняются shell/root-попытки. DEMO-панель для старых локальных проверок
перенесена в Настройки, доступна только в DEMO.

## Погода: честное ограничение

Приложение com.liontech.weather, version 0.2.26020500, изучено по APK из
полевого ZIP 20261018_130702_360_34876; декомпиляция JADX 1.5.6, 109 ошибок
в других методах. Ключевые классы CacheRepository, SpUtils и WeatherService
прочитаны; ошибки декомпиляции не считаются доказательством отсутствия API.

Полный weatherState/город сохраняется через приватный MMKV.defaultMMKV().
WeatherService.onBind возвращает null; в package dump нет экспортированного
провайдера полного прогноза или виджета. change_city_action не несёт прогноза.
GET SYSTEM_ANDROID_WEATHER_NEWS=721921 в реальном логе вернул NO_DATA, а DTO
содержит sunrise/sunset/high/pressure, не текущие температуру/город/время.
Значение high не используется как текущая температура.

Доступный публичный способ встроить чужую Activity в обычный APK не найден.
В этой версии полного чтения/встраивания прогноза НЕТ. Вместо вымышленного +8°
на ГУ — «—° / Штатная погода / Открыть прогноз», открывается установленная
com.liontech.weather.SplashActivity по нажатию. Автозапуска, запроса обновления,
сетевого клиента, доступа к приватным файлам и загрузки чужого кода нет.
Сама штатная погода может обновиться при ручном открытии — это не блокируется
и не выдаётся за гарантированно офлайн-операцию. Без неё в локальном DEMO
сохранён явно подписанный тестовый прогноз. При переходе в live DEMO-прогноз
сбрасывается, включая начальный кадр обновления потоков состояния.

## Проверка на ГУ после установки

1. START → 1 → JelandOS-0.5.0-connectivity-preview.apk. Probe не обновлять.
2. При необходимости разрешить чтение индикаторов в Настройках Jeland OS.
3. В штатных настройках включить/выключить Wi-Fi, подключить имеющуюся сеть.
   Проверить значок после возврата; подключение не должно исчезнуть из индикации
   лишь потому, что основной интернет идёт через модем.
4. Отключить/подключить уже сопряжённый телефон штатным способом, проверить BT.
5. Сопоставить тип сети и полоски со штатным модемом. При отсутствии доступа
   ожидается нейтральная индикация, а не максимальный сигнал.
6. «Автомобиль» должен открыть заводские настройки. Виджет погоды — штатную погоду
   только по нажатию. Нового диалога интернет-загрузки от Jeland OS нет.
7. Сохранить логи Jeland OS либо START → L, если что-либо не совпало.
