# Автоматические проверки GitHub

Workflow: `.github/workflows/android-checks.yml`, имя **Android CI**,
обязательная проверка для правил ветки — **Android checks**.

В mrRadik/jeland-os проверка уже включена в активный `main-pr-required`:
источник GitHub Actions, ветка PR должна быть актуальна относительно main.
Остальные правила и исключения владельца сохранены.

Запускается для каждого PR в main, при каждом изменении main и вручную
через Actions → Android CI → Run workflow после появления workflow в main.
Фильтров по файлам нет: обязательная проверка не должна пропускаться из-за
изменения только документации. Новый коммит в PR отменяет его устаревший запуск.

На стандартном Linux-сервере GitHub с JDK 21 и Android SDK 36 выполняются:
SDK и command-line tools устанавливаются явно: наличие sdkmanager в образе
GitHub не предполагается.

```
bash ./gradlew --no-daemon --console=plain --stacktrace --continue \
  testDebugUnitTest lintDebug assembleDebug compileDebugAndroidTestKotlin
```

Проверяются сборка debug APK, JVM-тесты, Android Lint и компиляция Android-тестов.
Ошибки любой из этих задач делают проверку красной. Отчёты JUnit и Lint доступны
в Actions как `android-check-reports` в течение 7 дней; число тестов выводится
в сводку запуска. JVM-тесты не заменяют Android UI-тесты и проверку на ГУ.
Lint baseline не используется: ошибки блокируют проверку, предупреждения
остаются видны в отчёте и не считаются ошибками сборки.

Сервер не получает ключ подписи релизов, токены пользователя и доступ к машине.
Workflow работает с `contents: read`, не публикует релизы и не устанавливает APK.
Для проверки PR используется обычный `pull_request`, а не `pull_request_target`.
Кэши Gradle в PR только читаются; действия закреплены за конкретными commit SHA.
Проверочные APK в релизы и артефакты не загружаются.

## Как посмотреть результат

Откройте PR → Checks → Android checks. Зелёная отметка означает, что проверки
прошли; красная — откройте упавший шаг и отчёт, исправьте код и отправьте новый
коммит в ту же ветку. Проверки запустятся снова автоматически.

## Как сделать проверку обязательной

После первого успешного запуска: Settings → Rules → Rulesets → main-pr-required.
Сохраните существующие ограничения и добавьте Require status checks to pass,
выберите **Android checks**, источник GitHub Actions. Не добавляйте эту проверку
в список исключений владельца: правило должно действовать и при принятии
собственных PR. После настройки нужны зелёные проверки и решение владельца.

Проверки не выполняют автоматическое слияние. Наличие зелёной отметки не даёт
участникам дополнительных прав на main.
