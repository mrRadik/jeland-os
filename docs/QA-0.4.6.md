# 0.4.6 — Climate preview

## Изменения

- Три независимых переключателя направлений; последнюю активную зону выключить нельзя.
- Таблица команд HVAC 0x5000A/6: SET 0 лицо; 1 лицо+ноги; 2 ноги; 3 ноги+стекло;
  4 стекло; 5 лицо+стекло; 6 все. Это enum, не битовая маска.
- OEM GET: 0/1/2/3/4/6/7. В частности GET 6 — лицо+стекло, не все.
- Вентилятор 1…10; в DEMO сохранён прежний нулевой уровень через минус/ползунок.
- Питание 18, AUTO 4 (только ON в live), A/C 1, рециркуляция 8,
  обогрев заднего 80, обогрев лобового 65. SYNC — DEMO; live заблокирован.
- Нижняя панель: сиденье водителя, его температура, вентилятор, AUTO, A/C,
  рециркуляция, заднее стекло, лобовое стекло, температура пассажира, его сиденье.
- Прежняя кнопка front defrost (24) в нижней панели теперь не используется:
  обогрев лобового — отдельный API (65), не изменение направления обдува.
- Изменён только климат; исправлено наложение контекстного уведомления на часы:
  максимальная ширина 400 dp вместо 520 dp. События и таймеры прежние.

## Штатная панель

Свежий SVHvac из JelandProbeLogs_20261018_130702_360_34876.zip разобран локально.
HvacService.onStartCommand принимает явный service intent и extra type=CLOSE_PANEL.
Закрытие view/b.l() игнорируется во время 300 мс анимации; по её окончании
view/b.n() может снова показать панель, если HvacService.a() остаётся true.
Сам CLOSE_PANEL меняет флаг только при определённых конфигурациях b()/c().
Не выдаём startService без ошибки за подтверждение исчезновения окна.

Теперь только после собственной VDS-команды создаётся окно наблюдения 3.2 с:
OPEN_PANEL → отложенный UI-only CLOSE_PANEL через 380 мс; резервные попытки
450/1000/1700/2500 мс. Всего максимум 5, интервал не менее 350 мс.
При паузе/переподключении наблюдение отменяется. Нет root, overlay, force-stop,
disable, повтора VDS SET, инъекции клавиш либо изменения OEM APK/конфигурации.
Не используется CLOSE_HVAC_BT: он отправляет дополнительные автомобильные команды.

Это ограниченное улучшение скрытия, НЕ подтверждённый quiet API и НЕ гарантия
отсутствия короткого всплытия/повторного открытия на данной прошивке.
Журнал: HVAC_UI_OPEN_OBSERVED, HVAC_UI_CLOSE_REQUEST reason=..., *_UNAVAILABLE.

## Проверка

Локальная сборка assembleDebug, testDebugUnitTest, assembleDebugAndroidTest.
Unit-тесты покрывают все SET/GET, каждое переключение зоны, неизвестные/просроченные
данные, DEMO persistence новых кнопок, ограничение и отмену UI-close window.
UI-тесты в BlueStacks 127.0.0.1:5556: семь комбинаций, последний переключатель,
обогревы из нижней панели и popup, вентилятор 10, обе темы, снимки Compose root.
Физический автомобиль в этой проверке не подключался.

Результат: 54 unit-теста, ошибок 0. Полный прогон 27 Android UI-тестов,
ошибок 0 (108 с). Первый прогон выявил наложение уведомления на часы;
после уменьшения его ширины полный повторный прогон успешен.
Снимки: screenshots/qa-0.4.6, тёмная и светлая темы.

## Ручная проверка на стоянке

1. Обновить Jeland OS через START → 1, выбрать APK 0.4.6; данные не удалять.
2. Подключить ГУ и разрешить команды. Сверить выделенные направления с родным UI.
3. Проверить семь комбинаций, по одной команде с ожиданием обратного чтения.
4. Проверить температуру, вентилятор, A/C и рециркуляцию: появляется ли OEM-панель,
   закрывается ли и открывается ли снова. Снять короткое видео при повторном показе.
5. Отдельно проверить оба обогрева стёкол и их обратную индикацию.
6. START → L: забрать автоматический журнал OS с таймингом попыток скрытия.

Старые APK сохранены для отката. Новых разрешений нет. Probe не менялся.
