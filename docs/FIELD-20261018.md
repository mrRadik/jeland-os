# Проверка Jeland OS / Probe 18 октября 2026

Вход: JelandProbeLogs_20261018_100650_415_38376.zip,
JelandClusterDiag_20261018_100703_405_884.zip и два фото владельца.
Владелец подтвердил, что фото давления сделано примерно одновременно с логом.
Только локальный анализ, подключения к машине не выполнялись.

## Bluetooth — подтверждённая причина

В журнале 12:06:13.567 и 12:06:30.419: NameNotFoundException для
com.desaysv.ivi.vds.bt.service.BTService. Такой класс указан в устаревшем
VDServiceDef, который OEM оставил и в новом APK.

Фактический manifest из приложенного SVVDSBluetooth.apk:
com.desaysv.service.bluetooth.service.VDBTService, exported=true, enabled=true,
action.desaysv.ivi.vds.bt.SERVICE. У сервиса нет отдельного permission attribute.
Диспетчер h.h обрабатывает MUSIC_INFO=262945, MUSIC_PLAY=262948,
MUSIC_PROGRESS=262952; h.g.r вызывает play/pause/skipToPrevious/skipToNext.
Форматы Parcelable и ключ status/info совпали с Probe.

Probe 0.6 меняет компонент, не добавляя pairing, контакты, audio focus или автоплей.
Физический результат чтения/команд ещё проверить. В media_session.txt уже есть
активная A2dpMediaBrowserService с метаданными и state=3, то есть музыка на ГУ есть.

## Шторка

0x50010/124: OPEN=1, CLOSE=2, HALF=3. Обратная связь 0x50001/10.
OEM VrVehicleMgr проверяет closed=1 и open=5. Полевой журнал 17 октября:
16:21:02 SET1 → feedback2 → 16:21:15 feedback5;
16:21:26 SET2 → feedback4 → 16:21:41 feedback1.
Это подтверждает 2 открывается и 4 закрывается. RAW3 отображается как «частично
открыта», но точные 50% и enum всех особых состояний не доказаны.

0.4.4 показывает обратное состояние, визуализацию конечных положений и частичного
положения, не подменяя его запрошенным. HALF не объявляется подтверждённым по SET.
Дополнительный диалог каждой команды убран по просьбе владельца; общее разрешение
записи на стоянке, отмена по lifecycle и отсутствие повторов SET сохранены. STOP нет.

## Штатное окно климата

В локальном HvacService.onStartCommand найден type=com.desaysv.svhvac.CLOSE_PANEL:
вызывает закрытие панели; при соответствующей конфигурации меняет isHvacShow=false.
Это UI-операция, не выключение климата. В HvacMainModel cmd9 вызывает показ панели.
0.4.4 отправляет ограниченный CLOSE_PANEL до команды и через 300/1000 мс после неё.
Перед вызовом проверяется exported/enabled; ошибки журналируются, CAN-запись не
повторяется. Запросы прекращаются после ухода из Jeland OS/сброса разрешения записи.

Доступность этой точки на фактическом HVAC APK ещё не доказана: в новых архивах нет
HVAC APK и журнала работы Jeland OS. Поэтому это кандидат исправления, не полевой
успех. Новый START -> L сохраняет HVAC APK/пакет и нужные OEM-теги вместе с журналом OS.
Не отключаются пакеты, службы, overlay-разрешения, SELinux или системные предупреждения.

## Шины — предварительная калибровка

12:06:10.080: INFO140=[182,171,175,169]. Начальная формула raw/70 даёт
2.60/2.44/2.50/2.41; фото штатной панели: ПЛ2.5, ПП2.3, ЗЛ2.4, ЗП2.3 бар.
Введена минимальная одноточечная коррекция raw/70 − 0.1: округление до десятых
совпадает с фото. Это НЕ доказательство OEM-формулы на всём диапазоне давления.
Исходные RAW сохраняются; нулевое давление не превращается в норму/нет данных.

Порядок массива временно ПЛ/ПП/ЗЛ/ЗП. Значения первого и третьего каналов различимы;
два правых на фото одинаковы, их перестановку нельзя исключить. Все значения UI
помечены ≈, оговорка доступна в панели шины/диагностике. Для окончательной проверки
нужна контролируемая разница на одной правой шине и новый снимок/лог.
Температуры 21/12/16/12 °C видны на OEM-приборке, но источника в VDS ещё нет:
INFO143/144/173…176 вернули IS_NULL. Температуры не выдумывались.

## RPM

INFO62 на холостом ходу [0,186…190], raw×4 даёт похожие 744…760.
В журнале, продолженном утром, встречаются [0,93…98] и [0,220…231]; владелец
сообщил обратную зависимость при повышении оборотов. Единственная точка холостого
хода не позволяет восстановить шкалу. Вывод рассчитанных RPM отключён, RAW сохранён.
Не подставлены ни обратная формула, ни догадка о переполнении младшего байта.

## Приборка

during-physical-2.png — полный screencap 1920×720 с голубой меткой JELAND TEST.
SurfaceFlinger: external display, hwcId=2, layerStack=2; окно Probe есть в output
layers и помечено composition=DEVICE. Значит Android-композиция до HWC работает.
Ни штатных шкал, ни фона OEM-приборки на этом Android-выходе нет. Отсутствие метки
на физической панели нельзя объяснять только неудавшимся Presentation; ещё нужно
установить маршрутизацию/режим физического входа приборки. Автоматически менять
его или заменять/гасить штатные шкалы небезопасно, этого в сборках нет.

## Графика

ContentScale.Crop заменён вписыванием полного исходного изображения. Отрисовка
дверей, капота/багажника и touch targets привязана к общему прямоугольнику PNG,
с резервом на открытые двери. Размер главной/климата/избранного не изменялся.
Предупреждение стало коротким («Открыта водительская дверь»); техническая оговорка
о неподтверждённой скорости больше не растягивает основной текст уведомления.

## Следующая проверка на стоянке

1. Обновить Jeland OS до 0.4.4; проверить шторку и смену состояний до конца движения.
2. Разрешить команды и изменить температуру на один шаг: проверить окно штатного климата.
3. Сверить четыре давления со штатной панелью. Не использовать расчёты вместо TPMS.
4. Обновить Probe через START -> 2 до 0.6. Подключить телефон и штатную BT-музыку.
   Подключить BT API, прочитать трек, отдельно проверить PAUSE/PLAY/NEXT/PREVIOUS.
5. Завершить START -> L новыми скриптами: в ZIP должны быть os-app-journals,
   os-package.txt и applications.json. В присланном архиве этих файлов ещё нет.
