# 0.9.9 — аватар помощника и подготовка проверки аварийки

## Что подключено

В режиме ГУ (не DEMO), пока интерфейс приложения на переднем плане, отдельный клиент
подписывается на VR_STATUS 0x80002 и VR_TTS_STATUS 0x80004 в штатной VRService.
После успешной регистрации отправляет запрос SceneEngine view_avatar/showAvatar=false.
Начальная регистрация трактуется как отсутствие активного сеанса до первого события;
это допущение требует проверки на ГУ, особенно при запуске во время уже активного диалога.

ASR 1000/1001/1002 и TTS begin удерживают аватар видимым. ASR 1003 плюс завершённый
TTS возвращают скрытие. Нераспознанный формат, потеря связи или уход с экрана —
показать; повторяющиеся состояния не вызывают повторных запросов. Restore отправляется
только если клиент ранее успешно передал hide. Отказ startForegroundService ловится
и сохраняется в журнале, не выдаётся за выполненное скрытие. В DEMO запросов нет.

Никаких VR_STATUS_CONTROL SET, отключения микрофона, остановки пакетов, изменений
настроек системы, Accessibility или циклического подавления чужих окон.
Приостановка/уничтожение модели возвращает видимость. После аварийного завершения
процесса lifecycle-восстановление гарантировать нельзя; область activityFullPath
указана своим ru.jeland.os.MainActivity, но её поведение на этой прошивке ещё не проверено.

Запрос visibility найден в stock SystemUI SVScreenCleanView и DriveModeSwitchDialog:
package com.iflytek.autofly.sceneengine, action DATAUPLOAD, extra value с JSON
dt=active_care, type=view_avatar, activityFullPath, showAvatar. В CarPlay есть такой же
путь, но в декомпилированном методе не видно помещения сформированного JSON в Intent;
поэтому он сам по себе не считается доказательством работоспособности.
Parcelable VDAsr/VDTTS воспроизведены только в read-only OEM wire-порядке для событий.

## Аварийка: НЕ готовое управление

Домашняя карточка камер заменена красным двойным треугольником «Аварийная сигнализация».
Нажатие открывает честное пояснение и кнопку перехода в Probe >=0.17, раздел hazard.
Пакет/версия проверяются до запуска. В основной OS нет аварийных SET: allowlist их
не разрешает. Добавлено только чтение штатного 0x50004/79 в общий телеметрический журнал.
Нулевые/сырые данные не выдаются за подтверждённые ВКЛ/ВЫКЛ, картинка не мигает как
ложная индикация работающих ламп.

OEM ReadOnlyID.ID_HAZARD_LIGHT=79; AvmID.ID_REQ_HAZARD_LIGHT=24;
VDEventCarInfo.MODULE_AVM=327688 (0x50008). Значения запроса 0/1/2 не расшифрованы.
Probe 0.17 добавляет отдельно помеченный эксперимент: один выбранный RAW SET AVM/24,
ручное разрешение на стоянке и отдельное подтверждение; снимок INFO/79 до и после,
без ожидаемого значения, автосерии, повторов SET и cleanup SET при выходе.
Физическую кнопку и наружные лампы нужно проверить вручную. До подтверждения это
не замена аварийной сигнализации в дорожной ситуации.

Инструкция рядом с APK: Jeland-VDB-Probe-v0.17-README.txt. Результат нужен для
сопоставления команды с фактическим состоянием, а не только с кэшем Binder.

- **174 JVM-теста, 0 ошибок**. Новые проверки: ASR/TTS вместе и по отдельности,
  неизвестные состояния, потеря подписки, выход с экрана, запрет всех AVM/24 SET
  в production allowlist, наличие read-only канала 79.

  конкретный AVM/24, обратный INFO/79, отсутствие выдуманного expected/on/off.
- Подготовлены и скомпилированы 3 Android-теста с fake Context/Binder: visibility JSON,
  hide/active/idle/restore, дедупликация, отсутствие SET, отказ binding, Parcelable ABI.
  Они **не запускались**: локальный 127.0.0.1:5555 сейчас offline. UI-тесты этой версии
  тоже не запускались, новый экран визуально на эмуляторе ещё не проверен.
- Физический ГУ и его исполнительные механизмы не затрагивались.

Голос, клавиатура, частичный поиск, карта, граф и климат не менялись.

## Проверка пользователем

1. START → 1: OS 0.9.9. START → 2: Probe 0.17.
2. В режиме ГУ открыть OS, проверить отсутствие idle-аватара; вызвать помощника
   кнопкой/голосом, дождаться ответа и завершения. Затем выйти в штатный интерфейс.
   Если аватар не возвращается, прекратить проверку; журналы содержат AVATAR строки.
3. Аварийка: только на стоянке, по отдельной инструкции Probe. Сначала baseline
   физической кнопкой, лишь затем осознанный одиночный RAW-тест с подтверждением.
4. Сохранить журналы OS/Probe и собрать START → L. Не делать предположение об
   успешной команде только по SET_RETURNED или изменению кэша.
