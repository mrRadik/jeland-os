# 0.9.26 — обе OEM-ветки запуска камер

Пользователь сообщил, что кнопка не открывает камеры. Свежих OS-логов с нажатием в portable/logs нет (последний архив Probe от 22 октября), поэтому точная физическая причина не доказана. Найдена конкретная недоработка: из Launcher ранее перенесена только одна ветка.

Локальные первичные источники: work/launcher-20261019/jadx/sources/com/desaysv/launcher/f/a.java:f() и work/systemui-20261019/jadx/sources/com/android/systemui/shortcut/a.java:c(), e/b.java:i(). Оба проверяют CarConfig 55/112: если любой ==1, CarInfo MODULE_AVM/8=1, иначе VDEventRvc.AVM_ICON_PRESS (786834) с пустым Bundle через RVC. VDServiceDef задаёт action.desaysv.ivi.vds.rvc.SERVICE, com.desaysv.ivi.vds.rvc/.service.RvcService. Пакет RVC присутствует в старом дампе ГУ. Fake launcher shortcut не является самостоятельным Activity. Инженерный AVMTestActivity меняет статусы камер/сбрасывает AVM — его не используем.

CarConfigUtil/EolConfig/SystemUtil/ReserveConfigConstants задают: ro.desay.vehicle.protocol.version (по умолчанию 4.0), ServiceManager com.desaysv.ivi.vds.vdev.service.VehicleDevice, GET PROJECT_RESERVE_CONFIGS=917510 с type vehicle.persist.project.ext.configs3/4, ответ value — hex. Для 4.0 flag55=(config3[4]>>2)&1, flag112=(config4[5]>>7)&1, минимум 8 байт. Для 5.1 flag55=(config3[10]>>7)&1 при >=63 байтах, 112 не поддерживается. Нет SET конфигурации. Некорректный/недоступный ответ остаётся null в диагностике; маршрут RVC соответствует OEM default non-1, но не объявляется подтверждённой комплектацией.

OemCameraLauncher читает конфиг вне main и один раз выбирает путь. CarInfo делегирует прежнему DesayCarSession.openCameras. RVC bind только по нажатию, IVDBus тот же OEM ABI. GET VIDEO_SIGNAL=786635/status (VR-код также использует 2 как активное видео), при 2 ничего не переключается. Иначе SET 786834 с действительно пустым Bundle; никаких CMD_ID/VALUE, DISPLAY_ID, выбранного ракурса, калибровки или reset. Binder success не равен появлению физической картинки. После запроса только unbind, без закрытия/перезапуска native UI. Нет повторов/другой ветки при ошибке. Pending и штатный debounce 500 мс защищают от двойного icon press. Общий тайм-аут 3 с; generation отменяет поздний callback. MainViewModel.pause/onCleared отменяет незавершённый запрос. canOpen требует live connected writes-enabled; DEMO не отправляет. Package visibility RVC добавлена, новых разрешений нет. OEM-ограничения не изменяются и ложная скорость/питание не подставляются.
