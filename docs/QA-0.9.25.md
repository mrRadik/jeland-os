# 0.9.25 — переход музыка, таймеры форм и закрытие OEM-климата

Включает незавершённую перед дополнением пользователя работу 0.9.24. Верхняя строка теперь постоянно в одном overlay-слое; NavHost анимирует top/start/end insets за 320 мс FastOutSlowIn. Rail в одном координатном пространстве, климат не перемещается. Пара home/music: outgoing fade 180 мс, incoming fade 320 мс с задержкой 40 мс. Без blur/shared-element переработки компонентов. Для native navigation переходы None сохранены, при входе в неё inset snap. Уведомления сохраняют глобальный top=header+14.

ControlPanelInactivity: только Popup CLIMATE/SHADE/DRIVER/PASSENGER/DRIVER_TEMPERATURE/PASSENGER_TEMPERATURE. Задние сиденья внутри пассажирской формы. LaunchedEffect delay 4000 мс, сбрасывается при pointer/key событиях. Родитель наблюдает PointerEventPass.Initial и НЕ consume: кнопки и ползунки продолжают работать. Пока любой указатель pressed, таймера нет; отпускание начинает полный срок. Смена popup — новый срок; lifecycle ниже RESUMED приостанавливает; при возврате полный срок. Поддержан рекомендованный системой accessibility timeout. DEBUG/APPS/шины/аккумулятор/прочие информационные окна не авто-закрываются. Сам timeout только меняет popupName, не вызывает автомобильных команд.

OEM-первичный источник: work/hvac-current-20261018/jadx/sources/com/desaysv/svhvac/service/HvacService.java: CLOSE_HVAC_BT отправляет HVAC /9=2 для climate-display, НО также /64=2 и /51=0 для других подсистем — этот broad action не используем. view/b.java: k() отправляет OPEN_PANEL при начале показа; o() закрывает окно при снятии флага; открытие/закрытие имеют собственные 300 мс анимации. Простое CLOSE_PANEL во время анимации может быть проигнорировано, а без снятия флага n() снова открывает окно.

Реализация: dynamic receiver OPEN_PANEL только во время live connection; unregister/reset при stop/pause. ClimatePanelDismissal arm перед своей проверенной нетихой SET на 1500 мс. При сигнале открытия claim только один раз, затем session worker без фиксированной задержки отправляет отдельный UI-only /9=2. Повторные OPEN не создают loop. Проверки epoch/foreground/live/writes/bus и срока выполняются перед UI SET. Ошибка команды отменяет её ticket; старый callback не закрывает новое окно. Нет startService, CLOSE_PANEL/CLOSE_HVAC_BT, getRunningTasks, force-stop, root или записей /18, /51, /64. OEM UI SET отдельно от whitelist исполнительных команд, который по-прежнему не разрешает произвольный /9 из UI. Ошибка закрытия только журналируется, не вызывает повтор исходного воздействия. Journal HVAC_UI_DISMISS_SENT / HVAC_UI_DISMISS_ERROR.

Нетихие: HVAC 1/3/4/6/8 и /18=1, CAR 93/94/95/96/139/141/160. Тихие /76/78, /77, /18=2, обдув/обогревы /24/65/80, шторка/AVM не arm. Сигнал без недавнего собственного нетихого SET ничего не делает. Broadcast не аутентифицирует отправителя: ограничение 1500 мс и одноразовый ticket ограничивают эффект только снятием UI-флага после собственной команды. Если receiver недоступен или событие не пришло, нет таймерного fallback. Очередь/сам Binder могут добавить задержку; физическое время не гарантировано. Изменять OEM-анимации/прошивку не пытались.
