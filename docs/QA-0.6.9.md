# Jeland OS 0.6.9 — наружная температура и dock-команды

main, ru.jeland.os, versionCode 28. Probe не менялся. Проверенные BT/CarPlay
из 0.6.8 сохранены; экспериментальная навигация не включена в эту ветку.

## Конкретное отличие штатного нижнего климата

Из свежего ранее собранного APK com.android.systemui (архив Probe 19 октября)
извлечены исходники в work/systemui-20261019/jadx/sources рабочего чата.
JADX сообщил 13 ошибок в APK в целом; нужные ниже методы восстановлены
с явными вызовами, а не заменены догадкой по названию. Ключевой источник:
com/desaysv/model/svhvac/c/b.java, a(int,boolean) и b(int,boolean).

| Параметр | Был SET полноэкранного HVAC | Новый SET | Обратное чтение |
| --- | --- | --- | --- |
| Водительская температура | HVAC /10 | HVAC /76 | HVAC /10 |
| Пассажирская температура | HVAC /13 | HVAC /78 | HVAC /13 |
| Ступень вентилятора | HVAC /12 | HVAC /77 | HVAC /12 |

Температурные /76 и /78 действительно вызываются в SystemUI: тот же raw i,
не i+15, не умножение. Дополнительная аналитика i+15 в OEM-коде не является SET.
Значения 0–16 сохранены, LO/HI — прежние крайние значения. И +/- и ползунок
отправляют один новый SET; оба читают обычное состояние /10 и /13. При SYNC
читаются обе зоны и /3, клиент не дублирует температуру вторым SET.

Для /77 основание слабее: штатный HvacID прямо объявляет ID_AC_SET_BLOW_LEVEL=77,
а статус ступени — ID_AC_BLOW_SPEED_LEVEL=12. Явного вызова /77 в нижнем SystemUI
не найдено. Это ограниченный SDK-backed кандидат, НЕ полевое подтверждение.
В новой версии используется /77, raw 1–10 без сдвига; нужен тест физического
результата. Отсутствие изменения /12 не вызывает автоматического повтора или
возврата к старому SET /12. Полная тишина вентилятора пока не заявляется.

CarInfoService onSet → CarInfoManager.b формирует CAN-вектор из module/cmd/value.
Здесь нет обнаруженного универсального Bundle-флага «без UI» и проверки package,
которая сама объяснила бы разницу. Сам Binder был выбран верно; для температуры
различаются именно command IDs полного окна и нижней панели.

## Удаление подавления, а не новый таймер

Удалены OemHvacPanel, сброс /9=2, CLOSE_PANEL, callback закрытия, его задержка
и внедрённый тестовый close-обработчик. Ни температура, ни вентилятор, ни сиденья,
ни другие команды больше не отправляют служебные UI-SET или startService.
HVAC /9 остаётся только диагностическим GET/subscription. Прямые SET /10,/12,/13
убраны из actuator whitelist; /19 также только чтение.

Новые каналы температуры восстановлены по коду, но отсутствие открытия окна
нужно проверить физически. Для A/C, AUTO, SYNC, рециркуляции, направления, питания
и обогревов прежние подтверждённые команды сохранены. Не найден отдельный
silent setter для каждой из них, и тишина всего климата не объявляется решённой.
Они могут показывать штатную панель — теперь это не маскируется её закрытием.
OFF и обогревы, по наблюдению пользователя, уже не показывали панель; их wire
значения не изменены. Питание остаётся /18, UI-флаг не подменяет питание.

## Наружная температура

Подписка и GET существующего CarInfoService дополнены только HVAC /19.
OEM формула из CarPlay q1/k.java: raw * 0.5 - 55. Значения 135→12.5,
149→19.5, 150→20.0 совпадают с сообщёнными пользователем показаниями приборки.
Источник — датчик автомобиля, не прогноз. AAOS 25.0, климатическая уставка,
температура салона и оценки по давлению шин не используются как замена.

Нужен подключённый live-сеанс, ровно одно raw-значение 0–254 и возраст не больше
15 с. Отсутствие, 255, отрицательные, многозначные, устаревшие и будущие данные
дают «—°», а не DEMO. Проверка свежести раз в секунду при подписке UI — только
локальная, без отдельного Binder-опроса или интернет-трафика.
В карточке только крупная температура (включая половину градуса), без облака,
города, названия источника и подсказок. Нажатие всегда открывает штатное погодное
приложение. Если оно отсутствует, показано короткое сообщение, не DEMO-прогноз.

## Полевая проверка

1. START → 1 → JelandOS-0.6.9-dock-climate.apk, обновить поверх старой версии.
2. На стоянке подключить ГУ и разрешить управление. Проверить показание наружной
   температуры и открытие штатной погоды по нажатию.
3. При включённом климате отдельно водитель +/- и ползунок, затем пассажир:
   должен меняться физический климат; отметить отсутствие/наличие штатного окна.
4. Вентилятор проверить по одной ступени 1, 5, 10, сверить штатное показание /12.
   Если не меняется — сохранить лог, не нажимать многократно; автоматического
   fallback на старый канал нет. Это первая полевая проверка SDK-кандидата /77.
5. A/C, AUTO, рециркуляцию и направления проверить отдельно и сообщить, какие
   всё ещё показывают окно. OFF/обогревы не должны поменять прежнее поведение.
6. START → L. Нужны SET_REQUEST /76,/78,/77, GET /10,/13,/12,/19,/9 и READBACK.
   HVAC_UI_DISPLAY_CLEAR/HVAC_UI_WINDOW_CLOSE в новой сессии больше быть не должно.

Температуры шин этой версией не восстановлены. Приборка не переключается
автоматически: новые результаты исследования — CLUSTER-JCT-20261019.md.
