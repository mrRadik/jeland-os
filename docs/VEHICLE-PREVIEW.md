# Jeland OS 0.4.4 — реальные функции и UI

Обновление по логам 18 октября: шторка декодируется, повторный диалог убран;
OEM CLOSE_PANEL скрывает только панель климата (нужна полевая проверка доступности).
Шины выведены по предварительному порядку ПЛ/ПП/ЗЛ/ЗП; правые каналы пока не различены.
Расчёт давления скорректирован на −0.1 бар по синхронному фото. Это одноточечная
калибровка, а не заводская формула. Пересчёт оборотов отключён; RAW сохранён.

Это отдельное приложение `ru.jeland.os`, не прошивка и не Probe. Обновление сохраняет
макет главной и DEMO. Первый запуск — DEMO; режим ГУ выбирается вручную в Настройках.
Выбор режима сохраняется, разрешение записи — нет. При повторном запуске ГУ читается
автоматически, но сохранённые уставки не отправляются автомобилю.

## Подключено

Через ту же Binder-связку, что физически проверена владельцем в Probe:
`action.desaysv.ivi.vds.carinfo.SERVICE`, компонент
`com.desaysv.ivi.vds.carinfo/.service.CarInfoService`, normal permission
`ivi.vds.permission.SERVICE`. Собственные совместимые Stub/Proxy/Parcelable скопированы
из рабочего Probe без изменения wire-формата. Не используются JCT, root, priv-app,
платформенная подпись, CAN/HAL-команды и вмешательство в штатную приборку.

| Функция | Module / cmd | Запись / чтение |
|---|---|---|
| Температура слева / справа | 0x5000A / 10,13 | LO=0, 16…30°C=1…15, HI=16; шаг 1 OEM |
| Вентилятор | 0x5000A / 12 | UI 1…10, SET/GET без смещения. В полевом логе подтверждены 1,2,10,3; остальные промежуточные ступени отдельно не измерены |
| AC / питание / передний defrost / обогрев лобового | 0x5000A / 1,18,24,65 | SET1 включить, SET2 выключить; GET1/0 |
| Рециркуляция | 0x5000A / 8 | SET1/2; GET0 внутренний, GET1 наружный |
| AUTO | 0x5000A / 4 | Только SET1 включить; неподтверждённого OFF нет |
| Заднее стекло | 0x5000A / 80 | SET1 однократный toggle, исходный GET обязателен |
| Обдув | 0x5000A / 6 | Проверенные raw 0,1,3,4,5,6; для SET5/6 ожидается GET6/7 |
| Передние сиденья | 0x50001 / 93,94 вентиляция; 95,96 подогрев | UI0…3 → SET1…4; GET0…3 |
| Задний подогрев | 0x50001 / 139,141 | Слева/справа; выключение=SET1, включение минимум SET2 |
| Руль | 0x50001 / 160 | SET1 toggle, исходный GET0/1 обязателен |
| Шторка | 0x50010 / 124 | OPEN1, CLOSE2, HALF3; feedback 0x50001/10: 1 закрыта, 2 открывается, 3 частично (не доказанные 50%), 4 закрывается, 5 открыта |
| Четыре двери / багажник | 0x50004 / 15…19 | Только чтение 0 закрыто / 1 открыто |

Входящие подписки: `CMD_ID_ARRAY`; запись: `VALUE=int[]`. Нет преобразования `IS_NULL`
в нули. GET проверяет совпадение module/cmd. Данные старше 15 секунд становятся
недоступными в UI; disconnect очищает live-состояния. Один запрос пользователя — одна
отправка каждой выбранной команды; далее только GET. Для заднего ряда выбор двух
сторон означает две разные команды, не повтор одной. Параллельные команды не ставятся
в очередь, во время проверки обратной связи новые нажатия отклоняются.

Шторка показывает «запрошено» отдельно от feedback: конечные положения/промежуточные
статусы не выдумываются. Нет STOP. Ползунок вентилятора пишет только после отпускания.
Запись fan=0 не разрешена; выключение — отдельной командой питания. «+» на 10 и «−»
на 1 в режиме ГУ ничего не отправляют. Ограничение 7 из версии 0.4.0 было ошибочным:
полевой лог 17.10, 18:03:27.822 SET10 → 18:03:27.991 FEEDBACK10 → 18:03:34.865 GET10.
При сворачивании: блокировка записи, отмена очереди по epoch, отписка и unbind. Уже
отправленную Binder-команду отменить нельзя; никаких компенсирующих SET при закрытии.

## Предварительная телеметрия по формулам владельца

Все коэффициенты в `core/VehicleLive.kt`, объект `ExperimentalVehicleConversions`:

```
pressureBar = rawPressure / 70.0 - 0.1 // одноточечная коррекция по фото, не OEM
fuelPercent = rawFuel / 10.0
fuelLiters = 55.0 * fuelPercent / 100.0
litersToFull = 55.0 - fuelLiters
engineRpm = unknown // raw*4 опровергнут вне холостого хода; оставлен RAW
```

Fuel INFO68: принимается одно число либо два байта BE16; RPM INFO62 сохранён в RAW.
Например [3,232] → 1000 → 100% → 55 л. Если fuel вне 0…1000, показания недоступны,
не зажимаются в ложные 0/100%. Литры на карточке округлены. Давление INFO140: четыре
байта, предварительно ПЛ/ПП/ЗЛ/ЗП. В фото два правых значения одинаковы; их порядок
ещё проверить. Температура шин не выводится без подтверждённого источника.
Эти оценки не заменяют штатные показания/TPMS.

## Намеренно не подключено

SYNC (смысл enum не подтверждён), AUTO OFF, зеркала и остальные настройки, капот,
температура шин, скорость/передача, RPM, камера, BT-музыка, навигация, приборка.
Демо-плеер/карта/погода явно остаются DEMO. В режиме ГУ симуляторы не меняют реальные
состояния, неподтверждённые setter не доступны. Скорость неизвестна: открытый кузов
показывает консервативное постоянное предупреждение об открытой двери, а не
ложное утверждение движения. Не используйте это приложение вместо штатных предупреждений.

## Проверка на машине — только на стоянке

1. Установить APK поверх Jeland OS через START → 1 в ADB Toolkit; Probe не удалять.
2. OS → Настройки → Подключить ГУ. Дождаться подключения и проверить RAW/штатные значения.
3. Без разрешения записи убедиться, что климатические кнопки не отправляют SET.
4. Разрешить команды, проверить температуры по одному шагу, AC, вентилятор, рециркуляцию.
5. Проверить передние уровни 0/1/2/3 и выключение, задний подогрев, руль.
6. Шторка: свободный проём, кнопки OPEN/CLOSE/HALF отправляют сразу после общего разрешения записи.
7. Вручную открыть/закрыть четыре двери и багажник, проверить схему и подписи.
8. Сверить топливо, каналы давления и RPM со штатным экраном; записать RAW и физические значения.
9. Уйти на штатный экран и вернуться — запись снова должна быть заблокирована.

В журнале `Android/data/ru.jeland.os/files/JelandOS_vehicle_*.log` есть GET/EVENT,
SET_REQUEST/SET_RETURNED/READBACK и ошибки. Значение GET, совпадавшее ещё до SET,
не объявляется новым физическим срабатыванием. Логи могут содержать данные автомобиля.
Обновлённый пункт START → L в ADB Toolkit выгружает и Probe, и Jeland OS в один ZIP:
`os-app-journals`, `os-package.txt`, `applications.json`, logcat с тегом `JelandOSVehicle`.
В `applications.json` отдельно отмечено, удалось ли собрать журнал каждого приложения.
Локальные тесты/сборка не являются полевой проверкой именно этого APK; её ещё нужно провести.

Исходники до подключения сохранены в `.local/backups/vehicle-live-20261017_210211`.
